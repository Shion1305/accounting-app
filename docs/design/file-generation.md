## テンプレート管理

| 設定         | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| 識別・版     | 大学ID、帳票ID、対象年度、適用期間、バージョン・内容ハッシュ |
| ファイル     | 正しい空XLSX                                                 |
| シートの役割 | 出力、記入例・説明、計算参照、継続                           |
| ヘッダー     | 団体名、年度、期間、担当者等のセル                           |
| 科目対応     | アプリのcodeと大学の費目・表・ブロック                       |
| 明細配置     | 開始・終了行、列対応、結合、費目ごとの容量                   |
| 集計配置     | 費目小計、シート小計、全体合計、残高の位置                   |
| 継続         | コピー元、シート名、引継ぎ情報、総計の扱い                   |
| 印刷         | 用紙、向き、余白、範囲、繰返しタイトル、改ページ             |
| 入力・表示   | 必須項目、数値形式、長文の扱い                               |

同じ帳票構造の大学はテンプレート・科目対応・配置設定で追加する。新しい構造の場合は共通の変換・配置方式を拡張する。50〜100大学への拡張を想定し、大学別の知識をこの定義へ集める。

登録時にシート・セル範囲・結合セルの書込先・参照・数式エラー・マッピングを検証する。

## 最初の方式検証

正式な法政テンプレートと小さな固定データで、DBや画面の本実装より先に検証する。

1. 正しい空テンプレート・小計・総計と出力対象シートを確定する。
2. 0件・1件・枠ちょうど・1件超過を出力する。
3. Excel・PDFの書式を原本と比較する。
4. Excelの入力金額を変更し、合計が再計算されることを確認する。
5. 継続シート、長文、日本語、印刷タイトル、改ページを確認する。
6. 1,000件の時間・メモリ・サイズ・ページ数を測定する。

ExcelJSを第一候補とし、読み込み・再保存で必要な書式・数式・印刷設定・図形等が保たれるかを確認して採用する。失敗した場合は必要箇所のみのXLSX書換えや別エンジンを比較する。ExcelJSは数式計算を行わず、結合セルを伴う行変更にも注意点があるため、保持・計算・配置を別々に検証する。[ExcelJS公式ドキュメント](https://github.com/exceljs/exceljs#formula-value)

## 数式・複数シート

- 合計を固定値だけへ置き換えず、SUM等の数式を持たせる。
- 正しい既存式を保持し、シート追加・配置変更に必要な参照だけ更新する。
- 小計を含む範囲の再SUMや累計値の再合算で二重計上しない。
- 他シート参照、共有数式、絶対・相対参照、循環参照を検証する。
- SUMを必須とし、採用書式で使用するSUBTOTAL・IF・COUNT・COUNTA等も確認する。早稲田追加時はVLOOKUPも対象。
- `#REF!` 等を0円で隠さず、出力失敗として扱う。

Data Frameの行を費目ブロックへ配置し、容量超過時は指定の継続シートを追加する。値だけでなく書式・結合・行高・列幅・式・印刷範囲を引き継ぎ、団体名・年度・連番を設定する。

全取引が一度だけ明細または費目集計へ反映されることを照合する。元から複数シートあるブックでも、記入例や参照シートを継続シートとして誤用しない。

Excelのシート追加と印刷改ページは別に扱う。集計型帳票は取引件数だけを理由に複製せず、必要なら認められた明細別紙を追加する。継続シート・別紙の提出可否は大学ごとに確認する。

## 空データ・長文・数値

取引が0件でも、帳票に必要な団体・年度・補助情報が揃っていれば空の明細を持つテンプレートを生成し、サンプル値を残さず当期の実収入・実支出を0にする。繰越を含む帳票合計は大学定義に従い、開始残高が2,000円なら取引0件でも帳票合計が2,000円になる場合がある。開始残高の不明を0にしない。固定書式に注記を追加できない場合、「データなし」はアプリ側に表示する。取引0件を理由に年度プロフィール等の不足検証を省略しない。

長文は折返しと行高で対応するが、固定の印刷レイアウトを壊すほど伸ばさない。限度を超える場合は継続行・別紙・入力修正要求を定義する。見えない切り捨てはしない。

金額は数値として書き込み、テンプレートの桁区切り・円・負数の表示形式を維持する。ユーザー入力文字列をExcel式として扱わない。

## PDFと実行環境

生成したExcelブックをLibreOfficeで再計算・PDF変換する方式を第一候補とする。ExcelとPDFで別々の帳票レイアウトを実装しない。[LibreOfficeの変換機能](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

変換は専用コンテナで行う案とし、Cloudflare Containersを候補にする。Workers Paidプランと追加運用が必要なため、採用条件として確認する。[Cloudflare Containers](https://developers.cloudflare.com/containers/)

- 再保存したExcelを配信するか、保持したブックへ計算結果を反映するかは、書式保持検証で決める。
- Excelを開いたときの再計算設定だけでPDFの金額を保証しない。
- 出力対象シートと印刷範囲を指定し、記入例・説明・参照リストをPDFへ混入させない。
- 全シートを強制的に1ページへ縮小する設定を使わない。
- 日本語フォントを確認し、置換する場合は文字幅・改ページと提出品質を検証する。
- 要求ごとに一時ファイルと変換プロファイルを分離し、同時実行で混線させない。終了・タイムアウト時に片付ける。

初期は同期生成でファイルを返す。履歴保存のためにキューやR2を追加しない。計測で同期処理が成立しない場合のみ、期限付き入力・ファイルの一時保存と非同期化を別途設計する。過去ファイルの再ダウンロード機能には広げない。
