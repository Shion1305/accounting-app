# DB取得・大学別整形・ファイル生成を分離する

会計出力は「DBから取得 → 大学別Data Frameを生成 → ファイルを生成」の3段階とする。大学ごとの入力・集計ルールとファイルの配置・変換を、DBやHTTPから独立して検証し、大学追加や実行環境の変更による影響を限定するために採用する。

DBモデルを直接Excelのセルへ書く方式は初期の記述量を抑えられるが、保存形式・大学の業務ルール・帳票ライブラリを一緒に変更することになる。中間契約の維持コストを引き受け、型付きの取得結果と帳票用データを境界にする。呼出順、履歴、障害処理は外側の実行処理に置く。

この分離だけで元データの不足は解決しない。購入日や領収書提出情報など、元になる事実を保存する責務は入力・DB側にある。

現在の設計は[出力パイプライン](../design/export-pipeline.md)、保存の責務は[会計データ](../design/accounting-data.md)を参照する。
