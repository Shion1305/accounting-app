更新日: 2026-09-27

位置付け: 提供サンプルの調査結果。最新の正式規則・運用の確定とは区別する。

[ドキュメント一覧](../README.md)

資料: `docs/waseda/会計報告書（2025年度） (1).xlsx`。 同じセル・書式を保持し、個人・保存環境メタデータを除いた[参照コピー](../references/waseda-2025.reference.xlsx)を同梱している。処理内容は[資料管理記録](../references/README.md)を参照。

活動実績・補助金状況はシート名で「必須」と明示されている。会計表だけ埋めて他を空にしたファイルを、全提出書類が完成したものとして扱えない。活動管理全般を初期3大学のために先行実装する必要はないが、早稲田対応時には年度別フォームでの補完か、活動・申請データの管理／取り込みが必要になる。

提供ファイルには2025年度のタイトルと、領収書提出説明の一部に2024年度の表記が混在する。最新の正式版かは別途確認し、過年度の説明や分類リストを無条件に再利用しない。

## 作成する書類と範囲

| 書類・シート                           | 提出・参照の区分                                 | 自動生成する範囲と残る作業                                                                                                                                                   |
| -------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `会計報告書（必須）`                   | 全サークル必須と`A1`に明記                       | 団体・記入者、年度収支・繰越、会長への報告日。`A51`の会長へのメール報告を、ファイル生成だけで完了した扱いにしない                                                            |
| `活動実績・記録用紙（必須）`           | シート名で必須と明記                             | 月別の活動日時・場所・人数、提出済みイベントの色、外部依頼活動の件数。支出が0円の活動も対象にできる入力が必要                                                                |
| `課外活動補助金申請・給付状況（必須）` | シート自体は必須。イベント欄は申請状況で条件付き | 決定コース、提出したイベント報告の番号・名称・支出合計・費目、受給額。`B3`の説明により未申請ならイベント欄は入力不要。シート全体を削除してよいとは読み替えない               |
| `領収書貼付用紙`                       | 領収書の提出状況による                           | 全て提出済み／今回貼付の選択と、今回の各ページの領収書総額。未提出領収書がある場合は添付を要求する説明がある。全て提出済みの場合にチェックした台紙自体の提出が必要かは要確認 |
| `リスト`                               | 分類番号・団体名、役職、補助金コースの参照表     | Excelの参照・入力規則のために保持し、提出用PDFでは出力対象外とする案。正式な提出範囲は最新版で確認する                                                                       |

2025年度の活動期間は`活動実績・記録用紙（必須）!A1`で2025年4月1日～2026年3月31日と明示されている。会計報告書も年度の全収支を要求するため、任意の月だけを抽出した結果を年間提出用の完成版として出力しない。月次確認用は提出用と区別する。

領収書は`領収書貼付用紙!B22`で原本を貼付し郵送または窓口提出するとされ、画像の貼付・PDF化で置き換えられるとは確認できない。原本の整理・提出や会長への報告は、ユーザーが実行・確認する別の業務である。エクスポート成功を理由に提出済み状態を更新しない。

## 帳票生成へ要求する入力形式（提案）

[大学別入力契約の読み方](README.md#大学別入力契約の読み方)に従い、共通の会計Snapshotに型付き`reportContext`を追加する案とする。`reportKind: "waseda_annual_report"`、`schemaVersion: 1`でプロフィール・活動・補助金・証憑情報の意味を識別する。これはPR #2に実装済みの型ではない。HTTPのエクスポート要求に会計配列を送らせず、アプリケーション側がDBから会計データと保存済みの年度情報を取得してSnapshotを構成する。

以下の必須性は提出用出力のアプリ検証案であり、セルがあることを根拠に大学の公式必須条件を断定するものではない。

### 団体・年度・収支

| 入力                                              | 型・単位                                                                                            | 必須条件・入力時点                                                   | 根拠／用途                                                                                  |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `organization.name` / `fiscalYear`                | 空でない団体名／西暦年の整数                                                                        | 提出用出力で必須。団体・年度設定                                     | `会計報告書（必須）!A3:B7`。2025年度の値を毎年度固定で流用しない                            |
| `profile.organizationClassCode`                   | 分類番号の文字列、または未公認を表す内部code                                                        | 提出用出力で必須とする案。年度設定                                   | `G5:H6`、`リスト!A2:B483`。番号と名称を対応させ、未公認は手入力の団体名を使う               |
| `profile.author.studentNumber` / `name` / `phone` | 学籍番号／氏名／電話番号の文字列                                                                    | 提出用出力で必須とする案。対象年度の記入者を登録                     | `B9:H11`。学籍番号・電話番号は先頭0や記号を失わない文字列とする                             |
| `profile.author.roleCode`                         | 大学指定の役職に対応する内部code                                                                    | 提出用出力で必須とする案。記入者登録                                 | `D12:H12`の入力規則、`リスト!D2:D4`の幹事長・副幹事長・会計。アプリ権限ロールから推定しない |
| `profile.chairReport.status` / `reportedOn`       | 状態`unknown` / `not_reported` / `reported`と日付`YYYY-MM-DD`。reported時は日付必須、それ以外はNULL | 会長へ報告した時に記録。提出用で必要な報告の完了確認は運用に合わせる | `A47:F47`、`A51`。出力日時を代入しない                                                      |
| `openingBalanceYen`                               | 確認済みの整数円                                                                                    | 年度収支・繰越の生成時に必須                                         | `A18:C18`、`E44:G44`。不明を0円にしない                                                     |
| `entries[]`                                       | 共通の収入・支出。日付・金額・詳細科目                                                              | 年度全体の取引が揃っていること                                       | `A18:H45`、`A49`。領収書提出済みの支出も含める                                              |
| `entryDetails[].sourceKey` / `reportingLineCode`  | 同一Snapshotの元取引キー／大学の収支行code                                                          | 共通科目から所定行へ対応できない時に補完                             | 会費・寄付・協賛・大学補助金、各支出費目。元取引キーの不在・重複を拒否する                  |
| `otherLineLabels`                                 | 「その他」の収入・支出行codeに対応する文字列                                                        | その他行に金額を出す場合に名称を要求する案                           | `A23:A32`、`E34:E43`。それぞれ10行を超える時の正式な継続方法は要確認                        |

`会計報告書（必須）!H2`には日付形式の案内があるが、記入日・提出日等の意味はこの案内だけでは確定できない。意味を確認してから日付フィールドを追加し、会長への報告日と同一視しない。記入者情報は個人情報であり、対象年度の帳票作成権限に合わせて扱い、テストや共有用サンプルには合成値を使う。

| `activities[].month` / `scheduleText`                             | `YYYY-MM`／日時・定期開催を表す文字列                             | 月ごとの配置に必要。判明した日時を記録           | `A6:A51`、`B3:B5`。毎週の練習も記載例にあり、必ず単一日付で表せるとは限らない                                        |
| `activities[].location` / `participantCount`                      | 場所の文字列またはNULL／非負整数人またはNULL                      | 分かる限り詳細に入力。未知はNULL                 | `B2`の指示。人数不明を0人に変換しない。全活動への一律の非空必須化は原資料だけで断定しない                            |
| `activities[].externallyRequested`                                | `true` / `false` / NULL（未確認）                                 | 外部依頼件数を集計する前に確認                   | `A55:H55`。定期開催を1活動とするか各回とするか、件数の単位は運用確認が必要                                           |

補助金未申請が確認できれば、イベント報告欄は入力不要とする。状態不明を未申請と判定しない。未申請時の受給額欄を空欄にするか0円とするか、申請済みだが決定待ちの場合をどう表すかは原資料だけでは確定せず、最新版の記入要領で確認する。

活動記録の空配列は「活動なしを確認済み」と「未入力」を区別する必要がある。年度フォームの確認状態を管理し、台帳が0件であることを理由に活動シートを完成としない。既提出のイベント報告に対応する支出が台帳へ未登録の場合は、合計を裏付ける確認済みの報告情報が必要となる。参照を捏造したり、報告の合計から取引を自動作成したりしない。

## 計算できる値と不足時の扱い

- 科目別の年度収入・支出、期末繰越は会計データと確認済み開始残高から算出する。`C45`の収入総額は開始繰越を含み、`G45`の支出総額は次年度繰越を含む。帳票の総額を共通モデルの実収入・実支出と取り違えない。
- 活動の外部依頼件数は、対象活動が網羅され、依頼状態と件数の単位が確認できた場合に算出する。活動日時・場所・人数は支出の摘要から自動確定しない。
- 緑色のセルはイベント報告の提出状態から生成する。色を業務状態の唯一の保存先にしない。
- 領収書のページ総額は今回割り当てた領収書から算出する。過去提出済み分は今回の貼付額へ重複加算せず、年度の支出集計には含める。
- 貼付用紙は追加利用が明示されている。活動欄・イベント報告欄・「その他」収支行の上限超過については同じ許可を推定せず、継続書式を確認する。どの場合も切り捨てて完成扱いにしない。
- 年度プロフィール、活動、補助金、領収書の不足は、それぞれのID・項目へ結び付けたエラーで補完先を示す。会計明細に不足がなくても、他の必須シートが未確認なら提出用パッケージの完成とは判定しない。
