# 横浜国立: 初期対象・正式資料の入手待ち

更新日: 2026-09-27

位置付け: 未調査項目と調査の完了条件。具体的な書類・入力必須条件は未確定。

[ドキュメント一覧](../README.md)

横浜国立大学は法政・明治とともに初期対応の対象である。ただし、現在提供されているローカル資料には横浜国立の会計書式・記入要領がない。必要書類の数、大学固有の入力、Excel/PDFの提出可否、継続シートの条件は確認できていない。他大学の書式から推測して必須項目を定義せず、未対応のまま管理する。[未決事項Q-01・Q-04](../plans/accounting-export.md#未決事項)を解消してから対応完了とする。

## 入手する資料

| 資料                                                 | 確認すること                                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 対象年度の正式な空テンプレート一式                   | 取得元・版・対象団体区分。会計表以外の添付書類・別紙を含む範囲                         |
| 記入要領・提出案内                                   | 必須／条件付き／任意の欄、提出先、ファイル形式、紙・署名・原本の要否                   |
| 公開された記入例、または機密性を確認した提供例       | 各欄の意味、費目と内訳の粒度、残高・集計の扱い。記入済み例を製品用テンプレートにしない |
| 行追加・複数ページ・継続シートの正式な説明           | 超過時の書式、番号の継続範囲、ページ小計と全体総計、ExcelとPDFの提出単位               |
| 補助金・領収書等の関連要領が参照される場合はその資料 | 制度・申請・活動・提出済み証憑との関係。別制度の要件を混同しない                       |

公開情報を取得した場合も、対象団体・年度に合うものかを確認する。学内限定の資料が必要な場合は、正規に提供された資料を根拠として扱う。

## 書類別に分析して記録する内容

正式資料を入手したら、本ページに次の表を実際の書類・シートごとに作成する。現時点では書類名や大学固有のフィールド名を仮定しない。

| 設計ポイント             | 調査・記録する内容                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------- |
| 作成する書類             | シート名、用途、全団体必須／条件付き／参照のみ、他書類との依存、PDFの対象          |
| 取引登録時に失わない事実 | 実購入日、用途・内訳、費目の粒度、活動・資金源等への関連の必要性                   |
| 団体・年度のプロフィール | 団体コード、担当者、所属・役職、報告日等の欄があるか。取引とは別の入力単位         |
| 領収書・申請との関係     | 既提出・未提出・不明の区別、帳票上の番号、複数費目への配賦、原本の扱い             |
| 残高と計算               | 繰越・現金・預金の扱い、総額に繰越を含むか、式と二重計上の防止                     |
| 会計外の入力             | 支出のない活動、補助金の申請・受給等が必要か。不要という結論にも根拠を記す         |
| 表示・継続               | 非表示列・コメント・図形・入力規則、行数上限、数式、印刷範囲、改ページ、追加シート |

各入力には「名前、型・単位、必須になる条件、入力者・時期、保存単位、根拠のシート・セル、未確認時の扱い」を記す。欄の存在や記入例と、正式な必須条件を分ける。

## 要求するデータ形式の決め方

共通の会計Snapshotを基礎とし、追加情報が確認できた場合に限り[大学別入力契約](README.md#大学別入力契約の読み方)に従う型付き`reportContext`を提案する。大学固有の`reportKind`やフィールド一覧は、書類・条件を確認してから決める。PR #2で横浜国立の入力契約が実装されているという意味ではない。

出力要求は大学・年度・対象範囲等を指定し、アプリケーション側がDBから必要な会計データ・関連情報を取得する。HTTP要求に会計配列を渡して不足した保存設計を回避する構成にはしない。計算できる合計と、後から復元できない入力事実を分け、必要な入力は[保存設計](../design/accounting-data.md)へ反映する。

## 対応完了の条件

1. 対象年度・団体区分に合う資料一式と正式な出典が確認できている。
2. 作成すべき書類一覧と、各欄の入力・保存・変換・算出の対応表がある。不明条件を空値や推測で埋めていない。
3. 必須情報の入力→保存→承認→再取得が検証され、既存データの不足を利用者が補完できる。
4. 空・通常・行数境界・複数シートのケースで、金額・数式・印刷・PDFを確認している。
5. 署名・原本・実際の提出など人が行う作業と、アプリが生成する範囲が明記されている。
