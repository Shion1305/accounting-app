| ---------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |

| `見本!B18:D23`、`F14:G22`          | 徴収月、合宿・大会別内訳。備考の例は「単価×人数」                                | 合計金額から人数・単価を逆算しない。必要なら内訳名・備考を記録する。人数と単価の構造化必須化までは見本だけで断定しない |
| `見本!H5`                          | 指定助成金から一部支出した旨の備考                                               | 費目とは別に資金源の情報が必要になる例。備考で足りるか、配賦額まで管理するかは追加要件次第                             |
| `書式!C28:H30`                     | 団体コード・団体名、記載責任者の学部・学科・学年・氏名、電話                     | 取引ごとではなく団体・年度の報告プロフィールで入力する                                                                 |
| `見本!D5`、`H25`、`C26`、`G25:G26` | 繰越金は預金と保有現金の合計。収入合計には開始繰越、支出合計には次年度繰越を含む | 確認済み開始残高が必要。帳票の「支出合計」を通常の実支出合計として再利用しない                                         |

団体情報の欄は書式に存在するが、見本の人数・単価・資金源の備考を全取引の必須入力とは扱わない。科目の細分化で表せる差異と、活動・資金源という独立した意味を持つ差異を区別する。

## 作成する書類と範囲

`書式`を基に年度の会計報告書を生成する。左側は収入・開始繰越、右側は支出・次年度繰越、下部は団体と記載責任者で構成される。`見本`は説明用であり、提出用PDFへ含めない。別の必須書類や原本提出条件は、このブックだけでは確認できていない。

## 帳票生成へ要求する入力形式（提案）

[共通の入力契約](README.md#大学別入力契約の読み方)に加え、型付き `reportContext` へ次の情報を持たせる。

| 入力                                             | 型・単位                                           | 必須条件・入力時点                               | 根拠／用途                                           |
| ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------- |
| `organization.name` / `fiscalYear`               | 団体名／西暦年の整数                               | 出力時必須。和暦への表示変換は出力側             | `書式!B2`、`F28:H28`                                 |
| `profile.organizationCode`                       | 文字列                                             | 出力時必須とする案。先頭0を保持                  | `C28`                                                |
| `profile.author`                                 | `name`・`faculty`・`department`・`grade`・`phone`  | 出力時必須とする案。対象年度の担当者を登録       | `C29:H30`。gradeは正の整数、他は文字列               |
| `openingBalanceYen`                              | 確認済みの整数円                                   | 繰越を含む会計報告では必須                       | `見本!D5`。不明を0にしない                           |
| `entries[]`                                      | 共通の収入・支出データ                             | 対象年度の取引。金額・科目・日付を保持           | 収支の費目・内訳を集計する基礎                       |
| `entryDetails[].sourceKey` / `reportingLineCode` | 元取引キー／内訳行を表す安定したcode               | 共通科目だけで所定の内訳へ分類できない場合に必須 | `B8:B16`の助成金別、`F14:F22`の大会・合宿別など      |
| `lineLabels`                                     | 内訳行codeに対応する文字列                         | 書式で可変の内訳名が必要な場合                   | 徴収月や活動名。固定見本の名称を実データへ流用しない |
| `lineNotes`                                      | 内訳行codeに対応する任意の文字列                   | 備考を記載する場合                               | `D18:D23`、`H5`の例                                  |
| `contributionDetails`                            | 内訳行code、任意の単価（整数円）・人数（非負整数） | 「単価×人数」を構造化して記録する場合のみ        | 見本の例であり、全取引への必須化はしない             |

共通科目の粒度で内訳を識別できるなら `reportingLineCode` を重複入力させない。複数の制度を「補助金」一つに集約した既存取引を、合計額だけで分割しない。1件を複数の内訳へ配賦する場合は金額の対応を別途保存する。

`profile.author.phone` は数値ではなく文字列で保持する。年度の担当者が変わっても過年度の帳票用プロフィールを現在のユーザー情報で上書きしない。

## 計算できる値と不足時の扱い

- 内訳・費目ごとの合計、開始残高からの次年度繰越は算出する。合計と内訳を両方加算しない。
- 人数・単価・資金源は合計金額から推測できない。任意備考は空でもよいが、必要な助成金別内訳が不明なら分類補完を求める。
- 取引が0件でも、確認済み開始残高や団体・担当者の欄が必要な場合がある。空取引を理由にこれらの不足を無視しない。
- 原本はZIPの `[Content_Types].xml` エントリのローカルヘッダ不正があり、同梱する参照コピーで修復した。本文の分析はセル・数式・図形に基づく。ZIP修復によって正式性や製品の出力品質まで確認済みとはせず、対象年度の書式確認と生成・印刷の受入確認を行う。既存数式の問題は修復対象に含めない。
