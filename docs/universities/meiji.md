# 明治: 初期対象・正式資料の入手待ち

更新日: 2026-09-27

位置付け: 未調査項目と調査の完了条件。具体的な書類・入力必須条件は未確定。

[ドキュメント一覧](../README.md)

明治大学は法政・横浜国立とともに初期対応の対象である。ただし、現在提供されているローカル資料には明治の会計書式・記入要領がない。提出書類、大学固有の会計情報、Excel/PDFの提出条件、複数シートの扱いは確認できていない。一般的な収支表や他大学の書式を代用して、対応済みとはしない。[未決事項Q-01・Q-04](../plans/accounting-export.md#未決事項)で資料と運用の確認を管理する。

## 入手する資料

| 資料                                           | 確認すること                                                              |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| 対象年度の正式な空テンプレート一式             | 取得元・版・対象団体区分。会計表、明細、添付書類等の必要な組合せ          |
| 記入要領・提出案内                             | 必須／条件付き／任意の区分、提出先、Excel/PDF・紙の要件、署名・原本の要否 |
| 公開された記入例、または機密性を確認した提供例 | 費目・内訳・備考の意味、帳票間の整合、残高の集計方法                      |
| 行追加・ページ追加・別紙の正式な説明           | 超過時の入力場所、連番、全体総計、印刷・提出の単位                        |
| テンプレートが参照する制度別の申請・証憑要領   | 補助金、活動、既提出領収書等の追加入力の有無と条件                        |

対象団体区分や提出先によって書式が異なるかも確認する。ただし、そのような区分が存在すると現時点で断定するものではない。年度・対象が異なる公開資料だけで必須項目を確定しない。

## 書類別に分析して記録する内容

正式資料を入手したら、作成すべき書類と入力フィールドの対応を本ページへ追記する。現時点では具体的なシート名・大学固有のフィールドは未確定とする。

| 設計ポイント   | 調査・記録する内容                                                                     |
| -------------- | -------------------------------------------------------------------------------------- |
| 提出パッケージ | 全ての書類・シートの名称、必須／条件付き／説明・参照用、Excel/PDFの生成対象            |
| 取引の事実     | 実購入日、用途・内訳、費目、資金源や活動との関係が必要か。初回登録で取得すべき項目     |
| 年度・団体情報 | コード、担当者・役職・所属、提出・報告日等の欄と必須性。対象年度の履歴を保持する必要性 |
| 証憑・提出関係 | 領収書番号、過去の提出先・提出状態、複数費目や複数取引への配賦、原本提出               |
| 金額・残高     | 収入・支出・繰越の区別、現金・預金別の記載、計算式、二重計上を避ける集計方法           |
| 会計以外の情報 | 活動・人数・補助金の申請や受給等が求められるか。台帳だけで充足するか                   |
| 継続・表示     | コメント・図形・非表示列・入力規則、行数上限、追加シート、数式・印刷・改ページ         |

各フィールドには「名前、型・単位、必須条件、入力者・時期、保存単位、根拠のシート・セル、未確認時の扱い」を記す。入力例に値があることと全取引で必須であることを混同せず、確認できない条件は未決事項として残す。

## 要求するデータ形式の決め方

[大学別入力契約](README.md#大学別入力契約の読み方)に従い、共通の会計Snapshotに収支と確認済み残高を保持し、書類から必要性を確認した追加情報を型付き`reportContext`で表現する案とする。具体的な`reportKind`・追加フィールド・必須検証は資料確認後に定める。PR #2に明治用の入力契約が実装済みとは扱わない。

エクスポート要求には大学・年度・期間等の選択条件を渡し、アプリケーション側でDBから会計・関連情報を取得する。HTTPへ会計配列を直接渡すことは要求しない。取引登録時に取得しなければ失われる事実があれば、出力モジュールだけで補うのではなく[保存設計](../design/accounting-data.md)と入力画面へ反映する。

## 対応完了の条件

1. 正式な出典、対象年度・団体区分、空書式・説明資料・必要な別紙が確認できている。
2. 書類一覧、入力契約、各欄の保存元または算出根拠が文書化され、大学固有の必須条件が確定している。
3. 新規入力と既存データの補完ができ、入力→保存→承認→再取得で必要情報を失わないことを確認している。
4. 空・通常・行数境界・複数シートのExcel/PDFで、総額・数式・表示・印刷の受入確認を終えている。
5. 紙・原本・署名・実際の提出に必要な人の作業が明示され、出力成功と提出完了を区別できている。
