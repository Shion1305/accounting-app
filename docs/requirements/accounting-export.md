# 会計出力の要件と受入条件

更新日: 2026-09-27

位置付け: 合意済みの対象・要求。完了条件の達成状況は実装計画で管理する。

[ドキュメント一覧](../README.md)

サークルの収支を会計項目で分類して登録し、大学指定の書式を維持したExcel・PDFを生成する。ExcelのSUM等の数式は出力後も動作し、複数シート・複数印刷ページでも明細と合計が一致することを目標とする。

## 採用する方針

1. データ取得、大学別Data Frame生成、ファイル生成を独立した3段階に分ける。
2. 実行者・出力条件・結果の履歴をDBへ残す。
3. 詳細な処理ログを実行IDで関連付ける。
4. 過去ファイルの保存・再ダウンロードは実装しない。
5. push・PRはフォーク `Shion1305/accounting-app` 内に限定する。

## 初期対象と機能

初期対象は依頼文にある法政大学・横浜国立大学・明治大学の3大学とする。要件定義書に記載された学習院大学・早稲田大学・徳島大学は後続の追加対象とし、立命館大学もサンプルの存在だけで初期対象へ追加しない。

- 会計項目のプルダウンと保存、既存取引の分類補完。
- 大学別の科目対応・セル配置・テンプレート切替。
- 年度・月・任意期間・全期間による対象指定。
- 現在の承認機能に沿った対象データの指定。
- Excel・PDF出力、ファイル名生成、処理中・成功・失敗の表示。
- 数式、数値表示、フォント、罫線、結合セル、印刷範囲、ヘッダー・フッターの保持。
- 複数シート、空データ、長文、未分類・未マッピング等への対応。
- DB実行履歴と履歴一覧、構造化された処理ログ。
- 単体・統合・実ファイル・ブラウザ・性能テスト。

会計項目の自由な追加・編集・無効化・並び替え、大学テンプレートのアップロード・設定編集は、将来対応できる構造にする。初期実装では管理画面を作らずコードで管理する。認証・課金・画像保存の全面的な作り直しは範囲外。

## 要件との対応

| 要件                     | 実装する箇所                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| ① 大学別切替             | カタログ、大学別定義、出力画面                                           |
| ② 項目プルダウン         | 項目マスタ、入力API・画面                                                |
| ③ 項目マッピング         | Data Frame生成と大学別科目対応                                           |
| ④ セル位置マッピング     | ファイル出力とテンプレート配置設定                                       |
| ⑤ Excelの書式保持        | 元テンプレートの利用、保持検証                                           |
| ⑥ PDF                    | 同じブックの再計算・変換                                                 |
| ⑦ 関数                   | 集計定義から式生成、既存式保持、編集後再計算                             |
| ⑧ 複数シート             | 費目別容量、継続設定、全体合計                                           |
| ⑨ 自動配置               | Data Frame整形と出力側のセル配置                                         |
| ⑩ 期間指定               | 期間正規化、D1抽出、画面                                                 |
| ⑪ 対象データ指定         | 現在の承認状態に沿った選択規則                                           |
| ⑫ ファイル名             | 大学・年度・期間・形式による命名                                         |
| ⑬ 完了通知               | 処理中・ダウンロード開始・失敗の表示                                     |
| ⑭ 必須入力               | 大学・年度・書式固有入力の検証                                           |
| ⑮ エラー                 | 入力・設定・変換・履歴の失敗分類                                         |
| ⑯ テンプレート管理       | コード管理、版・内容ハッシュ、将来管理画面へ拡張可能な定義               |
| ⑰ 金額表示               | 数値を保持しテンプレートの表示形式を利用                                 |
| ⑱ 空データ               | 空書式、合計0、サンプル値除去                                            |
| ⑲ 長文                   | 折返し・行高・継続・修正要求                                             |
| ⑳ ログ                   | 処理段階と実行IDによる構造化ログ                                         |
| 追加: DB I/O分離         | 取得 → 大学別Data Frame → ファイル出力                                   |
| 追加: DB実行履歴         | accounting_exportsと履歴画面                                             |
| 追加: 再ダウンロード不要 | ファイル・入力全体の恒久保存を行わない                                   |
| 非機能                   | 定義による大学追加、通常3クリック、1,000件測定、金額整合性、サークル権限 |

## 完了条件

- 初期3大学で、正式テンプレートに沿うExcel・PDFを取得できる。
- Data Frame生成とファイル出力をDBなしで個別に検証できる。
- 会計項目が入力から立替承認、分類補完、出力まで維持される。
- 出力対象の明細・費目合計・全体合計・残高が一致する。
- 2枚目以降、空データ、長文でも欠落・重複・書式崩れがない。
- Excelを編集するとSUM等の式が再計算される。修復警告や数式エラーがない。
- PDFの全ページに欠字・文字切れ・不要ページがない。
- 実行者・条件・結果のDB履歴と、実行IDで追える処理ログが残る。
- 他サークルのデータ・履歴へアクセスできない。
- `pnpm check-types`、`pnpm lint`、`pnpm build` とテスト一式が合格する。
- 性能測定結果、移行手順、テンプレート追加・更新手順を残す。
