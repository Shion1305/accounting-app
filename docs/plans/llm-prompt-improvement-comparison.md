# Solのプロンプト改善比較

2026-10-12に実施した、Solの追加指示の比較計画。[原因分析](../reports/llm-file-editing-failure-analysis-2026-10-12.md)で見つかった手戻りを、指示の追加で減らせるか調べるために作成した。

計画した24応答はすべて実行済みで、結果は[比較レポート](../reports/llm-prompt-improvement-comparison-2026-10-12.md)にまとめている。以下には実行前に決めた条件を残す。ハッシュと実行順の原記録は、Git管理外の `experiments/llm-export/artifacts/diagnostics/sol-prompt-comparison-2026-10-12/plan.json` に保存している。

## 比較条件

| 項目   | 固定する条件                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------- |
| モデル | `gpt-6.1-sol`                                                                                                             |
| 入力   | 前回と同じ4書式の参照コピー・合成JSON                                                                                     |
| A      | 前回とバイト単位で同じ共通プロンプト                                                                                      |
| B      | Aに[追加指示の本文](../../experiments/llm-export/prompts/avoid-editing-pitfalls.md)を付加。編集上の状態説明・見出しは除く |
| 反復   | 各書式・各条件3回、計24応答。各試行で新規コンテナ                                                                         |
| 上限等 | 出力8,000、reasoning medium、default tier、1GB、ネットワーク無効                                                          |
| 評価   | 前回と同じ独立評価器・正解。途中で変更しない                                                                              |
| 順序   | 同じ書式・反復をA/Bの組として直列実行。A先行・B先行を各6組                                                                |

最初に4書式を各条件で1回ずつ、計8応答を実行する。費用と結果を監査してから残る16応答へ進む。不合格も結果に残し、失敗した試行だけをやり直すことはしない。途中でプロンプトを変える場合は別の条件として記録する。

今回は、すでに使った書式と少量の入力で品質と効率を比べる。新しい書式にも通用するかは別の検証が必要になる。また、Bは複数の注意事項をまとめて追加するため、個々の指示の効果までは切り分けられない。

## 予算と記録

実験IDはA=`sol-prompt-baseline-2026-10-12`、B=`sol-prompt-improved-2026-10-12`。各台帳の送信予算を$3.50に固定し、合計$7。前回推計$2.924513275との合計予算は$9.924513275である。前回の台帳・凍結済み結果には追記しない。

Solの登録料金は入力$2、cached入力$0.10、cache write $2.50、出力$10 / 100万トークン。1GBコンテナは初回20分相当$0.03で推計する。実行前に[公式料金表](https://developers.openai.com/api/docs/pricing)と一致を確認した。確定請求額ではない。

ゲートウェイは1リクエストにつき、最大100,000入力・8,000出力トークンとコンテナの分として$0.36を予約する。応答後に使用量から推計額を求め、予約と置き換える。12回分の最大予約額は$4.32だが、実際の費用が低ければ予算$3.50でも実行できる。次の予約額を確保できなくなった時点で止める。

この予算はローカルの送信制御に使うもので、提供元の請求額の上限を保証するものではない。

費用や送信結果が分からない場合、ファイル・コンテナを削除できない場合、固定ファイルの変更が見つかった場合は実行を止め、自動で再送しない。料金は今回の要求・応答・usage・コンテナ・削除記録から計算し直す。以前の監査スクリプトは初回実験の固定件数専用なので、そのまま流用しない。

## 比較する指標

まず、内容と書式の保持が検査に通り、応答も完了したかを比べる。そのうえで、コードの修正、計算エンジンで確認した範囲、ツール呼び出し数、各種トークン数、所要時間、推計費用、合格1件あたりの費用を調べる。出力が空の呼び出しと実際のエラーは区別する。ログの文字数も課金トークン数とは異なる。

Solは前回12/12で合格しているため、合格率だけでは改善を捉えにくい。確認作業を省いて速くなったケースも分かるように、計算や書式検査の範囲を調べる。今回は新たなローカルExcelでの確認は行わないため、再計算、修復警告、表示についての保証は増えない。

同じ書式・反復番号のA/Bを組にして比べ、書式別の結果も出す。キャッシュや実行時の変動もあるため、少数の結果から安定した改善率を示すことはできない。成功・失敗の例と実測値を合わせて判断する。

## 実行方法

以下のコマンドは有料の試行を新しく作る。実行済みの書式・条件・反復番号を重複して送らないようにし、順番は `plan.json` に従う。

```sh
node experiments/llm-export/run.ts --mode evaluate \
  --experiment sol-prompt-baseline-2026-10-12 --budget-usd 3.5 \
  --model gpt-6.1-sol --phase comparison --prompt-variant baseline \
  --max-output-tokens 8000 --cases ritsumeikan --repeat 1

node experiments/llm-export/run.ts --mode evaluate \
  --experiment sol-prompt-improved-2026-10-12 --budget-usd 3.5 \
  --model gpt-6.1-sol --phase comparison --prompt-variant avoid-editing-pitfalls \
  --max-output-tokens 8000 --cases ritsumeikan --repeat 1
```

`--prompt-variant` はevaluate/comparison専用で、`--repair-guidance` と同時指定できない。manifestにはvariant、送信した指示本文のハッシュ、合成後の全プロンプトのハッシュを記録する。
