# Solのプロンプト改善比較

2026-10-12に実行前の条件を固定。[原因分析](../reports/llm-file-editing-failure-analysis-2026-10-12.md)で見つけた手戻りを減らせるか、現行指示と追加指示を比較する。[条件・ハッシュ・実行順の記録](../../experiments/llm-export/diagnostics/sol-prompt-comparison-2026-10-12/plan.json)を正本とする。

追記: 計画通りの24応答を完了し、[比較結果](../reports/llm-prompt-improvement-comparison-2026-10-12.md)へ記録した。以下は実行前に決めた条件である。

## 比較条件

| 項目   | 固定する条件                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------- |
| モデル | `gpt-6.1-sol`                                                                                                             |
| 入力   | 前回と同じ4書式の参照コピー・合成JSON                                                                                     |
| A      | 前回とバイト単位で同じ共通プロンプト                                                                                      |
| B      | Aに[追加指示の本文](../../experiments/llm-export/prompts/avoid-editing-pitfalls.md)を付加。編集上の状態説明・見出しは除く |
| 反復   | 各書式・各条件3回、計24応答。各試行で新規コンテナ                                                                         |
| 上限等 | 出力8,000、reasoning medium、default tier、1GB、ネットワーク無効                                                          |
| 評価   | 前回と同じ独立評価器・正解。途中で変更しない                                                                              |
| 順序   | 同じ書式・反復をA/Bの組として直列実行。A先行・B先行を各6組                                                                |

最初に4書式を各条件1回ずつ、計8応答で実行可能性・費用・結果を確認し、残り16応答へ進む。静的不合格は比較結果として残し、都合のよい再試行で置き換えない。プロンプトを途中で変えた場合は別条件として扱う。

既知の書式・小さなケースによる回帰と効率の確認である。未見書式への一般化は評価しない。Bは複数の注意事項をまとめた変更なので、どの1項目が効いたかは切り分けられない。

## 予算と記録

実験IDはA=`sol-prompt-baseline-2026-10-12`、B=`sol-prompt-improved-2026-10-12`。各台帳の送信予算を$3.50に固定し、合計$7。前回推計$2.924513275との合計予算は$9.924513275である。前回の台帳・凍結済み結果には追記しない。

Solの登録料金は入力$2、cached入力$0.10、cache write $2.50、出力$10 / 100万トークン。1GBコンテナは初回20分相当$0.03で推計する。実行前に[公式料金表](https://developers.openai.com/api/docs/pricing)と一致を確認した。確定請求額ではない。

ゲートウェイは1リクエストにつき最大100,000入力・8,000出力・コンテナ相当の$0.36を予約する。実際の使用量で精算するため、12回の最大予約合計$4.32より小さい$3.50でも進められる可能性があるが、残り予約枠が足りなければ途中で止める。これはローカルの送信制御であり、提供元の請求額を保証する上限ではない。

未解決費用、曖昧な送信結果、後片付け失敗、固定ファイルの変更を検出した場合も停止し、自動再送しない。新しい台帳には以前の固定件数専用の料金監査を流用せず、今回の要求・応答・usage・コンテナ・削除記録から再計算する。

## 比較する指標

内容・保持・応答完了の合否を最初に比較する。そのうえで、生成コードの修正、計算エンジンの利用と確認範囲、ツール呼出し、入力・出力・cached・cache write・reasoningトークン、所要時間、推計費用、合格1件あたりの費用を比較する。空出力はエラー件数、ログ文字数は課金トークン数とみなさない。

Solは前回12/12合格だったため、合格率だけでは改善を捉えにくい。ただし、確認を省いて速くなった場合を改善とは判断しない。計算や保持検査の範囲を合わせて調べる。今回の自動評価はExcelでの再計算・修復警告・見た目を保証せず、新たなネイティブ確認はこの比較に含めない。

A/B間の同じ書式・反復で差を確認し、書式ごとの結果も出す。キャッシュ効果や実行時の変動があるため、この小標本だけで統計的な改善率を断定しない。成功・失敗の実例と測定値を併記する。

## 実行方法

以下は有料呼出し。各コマンドは新たな試行を作るため、実行済みの書式・条件・反復を重複送信しない。実際の実行順はplan.jsonに従う。

```sh
node experiments/llm-export/run.ts --mode evaluate \
  --experiment sol-prompt-baseline-2026-10-12 --budget-usd 3.5 \
  --model gpt-6.1-sol --phase comparison --prompt-variant baseline \
  --max-output-tokens 8000 --cases ritsumeikan --repeat 1

node experiments/llm-export/run.ts --mode evaluate \
  --experiment sol-prompt-improved-2026-10-12 --budget-usd 3.5 \
  --model gpt-6.1-sol --phase comparison --prompt-variant avoid-editing-pitfalls \
  --max-output-tokens 8000 --cases ritsumeikan --repeat 1
```

`--prompt-variant` はevaluate/comparison専用で、`--repair-guidance` と同時指定できない。manifestにはvariant、送信した指示本文のハッシュ、合成後の全プロンプトのハッシュを記録する。
